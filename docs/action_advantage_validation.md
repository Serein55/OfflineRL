# Spatial：同状态动作质量验证

状态：本轮验证完成（2026-10-13）；未修改π₀训练、权重公式、原reward/advantage sidecar或既有checkpoint。

## 最终结果

完成30个初始episode、57个分支状态、228条主对照rollout；另有一个状态的32条多种子rollout。所有主对照起点状态误差为0，同动作恢复验证通过，结果与实际终端goal一致。5项单元测试通过，原专家annotations文件SHA256未变。

下表是未参与拟合的7个任务，在22个同状态成功/失败配对（7个有区分信息的状态）上的结果，包含人为扰动对照：

| 分数 | 排序正确率 | episode bootstrap 95%区间 |
|---|---:|---:|
| 事件H5 | 50.0%（全部打平） | [50.0%, 50.0%] |
| 几何v2 | 31.8% | [11.0%, 48.4%] |
| 学习排序v3 | 81.8% | [60.0%, 100.0%] |
| 事件H50，仅诊断 | 88.6% | [75.0%, 100.0%] |

H50含后续策略执行和成功事件，不能以其高分宣称5步动作质量验证通过。

**自然动作证据不足。** 主实验57个状态中，仅2个状态的两个自然候选呈现一次成功、一次失败；保留任务只占1个。v3在这个保留自然对上排错，因此控制组81.8%不支持把它直接用于专家数据加权。开发集有16个成功/失败配对，v3正确率93.75%，同样不作为泛化证据。

几何v2失败的实例：task4物体在松爪掉落时仍向目标移动，会得到正向距离奖励；task5正常抓取/放置可能暂时增大距离。单纯靠近目标与动作质量并不等价。v3能利用接触和高度变化识别人为掉落，但需要更多自然动作对验证。

### 成功概率v4的独立种子检查

同一新快照task4/episode1/step40下，候选动作、动作历史、起点特征和前5步结果跨16个种子逐项完全相同。

| 分组 | 动作A成功 | 动作B成功 | B−A成功率差 |
|---|---:|---:|---:|
| 估计种子0–7 | 5/8 | 8/8 | +37.5pp |
| 独立验证种子8–15 | 2/8 | 6/8 | +50.0pp |
| 全16种子，仅描述 | 7/16 | 14/16 | +43.75pp |

由估计组得到`Q=[0.625,1.0]`，候选均值基线0.8125，`A=[−0.1875,+0.1875]`。原事件H5两者均为0；几何v2为A=0.071176、B=0.069850，反而偏好A。v3略偏好B，但分数差只有约0.000134。

验证组排序方向一致，有4个种子B成功/A失败、0个反向，精确配对检验p=0.125，**未达到预先设定的0.05门槛**。汇总16个种子的p=0.015625不是独立验证，不能替代验证组结果。因此输出保留估计advantage供研究，同时保守训练advantage置为[0,0]。这不是证明二者质量相同，而是当前独立验证样本不足。

v4提供了比手工事件更有希望的局部信号，但只检查一个开发状态，尚未验证跨任务泛化；不启动策略训练。接下来应扩大严格同快照的自然候选与独立续跑种子，将实测成功概率差作为质量标签，再验证预测器，而不是继续以更低ESS作为成功标准。

这轮测试针对部署时实际执行的5步前缀，不能据此否定所有完整50步chunk奖励；50步开环候选的独立反事实验证尚未进行。

## 要回答的问题

事件advantage能否在**同一状态下**区分不同动作的好坏，而不是区分轨迹进度或初始状态难度？最终成功是验证标签，前5步事件/几何特征是待验证的分数，两者分开。

## 对照设置

- 固定Vanilla 30k EMA策略，原128渲染、resize224、replan=5；Spatial 10任务，每任务3个官方初始状态。
- 沿参考策略轨迹在第40和90步分支；已经完成任务的轨迹不再生成后续分支。
- 每个分支状态比较4种5步动作：两个不同噪声种子的策略采样、保留转动/夹爪但平移置零、强制张开夹爪。
- 每个候选执行5步之后，用同一策略继续至成功或总计220步。续跑按绝对步数使用成对相同噪声种子。
- 人为扰动不预先标为坏动作，由实际任务结果决定。自然采样对单独报告，不能用“能识别人为掉落”代替“能区分自然动作质量”。
- 保存完整MuJoCo `MjData`（含contact/solver状态）、控制器、夹爪、观测缓存、环境时钟、NumPy RNG。同一快照执行同一5步动作两次，要求状态差<=1e-10；各分支起点状态差必须<1e-7。

原始状态重放方案在task4第90步出现约0.01状态差，已停止；`pilot/`不进入最终统计。跨进程重复名义上的同一初始状态也观察到漂移，`repeat_*/`不进入Monte Carlo估计。`monte_carlo_exact/`被消息中断，未拼接续跑；16种子组在`monte_carlo_exact_v2/`从一个新快照整体重跑。

## 按顺序验证的候选

1. **事件v1**：首次连续5帧接触+0.2、首次连续5帧失去接触−0.2、首次实际任务成功+1，按5步窗口求和。同状态同阶段的基线是常数，不改变排序，因此验证原事件分数即可。H50也记录，但包含后续闭环行为和可能的最终成功，不能当作独立的5步动作质量证据。
2. **几何v2**：事件H5加距离变化；起点有抓取接触时用物体到目标的平面距离进展/0.1m，否则用0.2×末端到物体距离进展/0.1m。门控固定于共享起点。公式在注册文件中固定，未用保留任务调参。
3. **排序v3**：仅用任务0/4/5的同状态成功/失败对，拟合8维线性pairwise logistic排序器；L2=1、每个有区分信息的状态等权。输入仅包含起点及5步后事件、接触、距离与高度变化，不读取后续成功标签作特征。任务1/2/3/6/7/8/9只作验证。该分数是偏好排序分数，不是校准后的Q值；同状态候选均值用于中心化。权重已冻结，见`frozen_ranker_v3.json`。
4. **成功概率v4**：同一完整快照、相同候选动作，多次用独立噪声续跑，估计`Q(s,c)=mean(success)`，再计算`A(s,c)=Q(s,c)-mean_candidate_Q`。单个开发状态task4/episode1/step40进行16种子检查，前8种子估计，后8种子独立验证。样本不足或差异不稳定时，将保守advantage置0，不为降低ESS而强制拉开权重。

v4检查仅限一个开发状态，不能推断对全部10任务泛化；重新启动时的参考轨迹可能略有差别，因此只比较同一次进程内生成的16个种子，且逐项核对动作历史、候选动作、起点特征、前5步结果完全一致。

## 统计边界

排序正确率仅比较同状态下一成功一失败的候选对，打平记0.5；独立初始episode为bootstrap单位，不能把多个动作对当作独立样本。只有1个有效对时出现[0,0]或[1,1]的bootstrap区间没有高置信度含义，必须同时报告有效对数。

开发任务只有5个具有成功/失败对比的状态、16个配对，排序器很容易过拟合。保留任务自然动作的有效对数是关键，控制组的高正确率不能替代它。

Monte Carlo使用配对成功差与精确配对符号检验。前8个种子用于拟合，后8个用于验证；汇总16种子的描述统计不冒充独立验证。
